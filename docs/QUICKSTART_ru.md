# Быстрый старт ARIZAgent (без навыков программирования)

Инструкция рассчитана на человека, который умеет устанавливать программы и копировать текст. Писать код не нужно.

**Время:** 30–60 минут в первый раз (дольше, если медленный интернет — Docker скачивает образы).

**Результат:** в браузере чат → вы описываете техническую задачу → получаете разбор по алгоритму АРИЗ-85-В.

---

## 0. Чек-лист «что нужно»

| № | Что | Зачем |
|---|-----|--------|
| 1 | Компьютер Windows / macOS / Linux, ~10+ ГБ свободно | Место под Docker-образы |
| 2 | [Docker Desktop](https://www.docker.com/products/docker-desktop/) (Win/Mac) или Docker + Compose (Linux) | Запускает все сервисы одной командой |
| 3 | Учётные данные **GigaChat API** | Модель, которая заполняет шаги АРИЗ |
| 4 | Этот проект (ZIP с GitHub или клон репозитория) | Файлы workflow и настройки |
| 5 | Браузер (Chrome / Firefox / Edge) | Интерфейсы чата и n8n |

Пока **не нужны:** Python, IDE, знание ТРИЗ «на отлично», патентная база.

Патентный поиск (Qdrant) для первого запуска **пропустите**.

Полный стек с патентами позже: `docker compose --profile patents up -d` (инструкция: [GOOGLE_PATENTS.md](GOOGLE_PATENTS.md)).

Описание сервисов и ссылки на документацию: [SERVICES.md](SERVICES.md).

## 1. Установить Docker

1. Скачайте Docker Desktop с официального сайта и установите как обычную программу.
2. Запустите Docker Desktop и дождитесь статуса **Running** (зелёный индикатор).
3. Если система попросит включить виртуализацию / WSL2 (Windows) — согласитесь и перезагрузитесь по инструкции установщика.

Проверка (необязательно): откройте терминал и введите:

```bash
docker compose version
```

Должна появиться строка с номером версии. Команда пишется **с пробелом**: `docker compose`, не `docker-compose`.

## 2. Скачать проект

**Вариант А (проще):** на странице репозитория GitHub → кнопка **Code** → **Download ZIP** → распаковать в удобную папку, например `Documents/ARIZAgent`.

## 3. Файл настроек `.env`

1. В папке проекта найдите файл `.env.example`.
2. Скопируйте его в тот же каталог с именем `.env`  
   (Windows: копировать → вставить → переименовать; уберите `.example`).
3. Откройте `.env` в Блокноте / TextEdit и при необходимости впишите пароли.  
   Для домашнего эксперимента значения по умолчанию обычно достаточны.  
   Ключ GigaChat, если он задаётся через переменные окружения, — по подсказкам в README; иначе ключ вводится позже в интерфейсе n8n (чаще так и делают).

---

## 4. Запустить все сервисы

1. Откройте терминал **в папке проекта**  
   - Windows: в проводнике в адресной строке введите `cmd` или `powershell` и Enter;  
   - macOS: Terminal → `cd` в папку;  
   - Linux: обычный терминал.
2. Выполните:

```bash
docker compose up -d
```

3. Первый запуск скачивает образы — подождите. Ошибки «port is already allocated» значат, что порты 3000 или 5678 заняты другим приложением: закройте его или измените порты в `docker-compose.yml` (см. FAQ).
4. Откройте в браузере:

| Адрес | Что это |
|-------|---------|
| http://localhost:3000 | OpenWebUI — чат, сюда будете писать задачу |
| http://localhost:5678 | n8n — сюда один раз импортируете алгоритм |

Если обе страницы открываются — шаг выполнен.

Остановить всё позже:

```bash
docker compose down
```

## 5. Настроить n8n (один раз)

### 5.1. Первый вход

1. Откройте http://localhost:5678
2. Создайте владельца (email + пароль) — это ваш локальный аккаунт n8n.

### 5.2. Нода GigaChat

1. Меню n8n → **Settings** → **Community nodes** (или **Commit nodes**, в зависимости от версии).
2. Установите пакет, указанный в README репозитория (обычно имя вида `n8n-nodes-gigachat`).
3. Дождитесь установки, при необходимости обновите страницу.

### 5.3. Импорт алгоритма

1. В n8n: меню → **Import from File** (или **Workflow** → Import).
2. Выберите файл: `workflows/ariz_85_v_3.json`
3. Откройте импортированный workflow.

### 5.4. Ключ GigaChat

1. Откройте любую ноду с названием шага (например `1_1_mini_task`).
2. В поле credentials нажмите создать / выбрать учётные данные GigaChat.
3. Вставьте Client ID / Secret / ключ — как требует форма (см. README и кабинет GigaChat).
4. Сохраните. Те же credentials подхватятся остальными нодами, если выбраны везде одинаково. Если какая-то нода подсвечена ошибкой — откройте её и выберите те же credentials.

### 5.5. Включить workflow и скопировать ссылку webhook

1. В правом верхнем углу включите тумблер **Active**.
2. Откройте первую ноду **Webhook**.
3. Скопируйте **Production URL** (вид `http://.../webhook/....`).  
   Для проверки «на столе» иногда используют **Test URL** — тогда workflow должен быть в режиме прослушивания теста. Для постоянного чата нужен **Active + Production URL**.

Сохраните URL в блокнот — он понадобится в следующем шаге.

## 6. Подключить чат OpenWebUI

1. Откройте http://localhost:3000 и создайте пользователя-администратора (первый запуск).
2. Перейдите в **Admin Panel** → **Functions** (или **Workspace → Functions**, в зависимости от версии).
3. **Create** → тип **Pipe** (или вставьте как Custom Function / Pipe — как в подсказке README для вашей версии OpenWebUI).
4. Откройте на компьютере файл `openai_functions/ariz_85_v.py` в Блокноте.
5. Скопируйте **весь** текст файла и вставьте в редактор функции в OpenWebUI.
6. Сохраните функцию, включите её (Enabled).
7. В настройках функции / **Valves** найдите поле **N8N_WEBHOOK_URL** и вставьте Production URL из n8n.
8. Создайте **New Chat**.
9. В выборе модели/функции укажите ваш Pipe (ARIZ / n8n).
10. Напишите задачу простыми словами, например:

> Нужно охлаждать электронный блок в герметичном корпусе. Вентиляторы ставить нельзя. Бюджет низкий. Предложи направление решения.

11. Нажмите отправить и **подождите**. Полный прогон АРИЗ может занять несколько минут: внутри много шагов подряд.

**Успех:** в ответе есть связный отчёт (резюме, постановка задачи, идеи решений и т.п.).

**Не успех:** текст про ошибку HTTP / timeout / пустой ответ — см. FAQ ниже.

## FAQ

**Страница localhost не открывается**  
Подождите 1–2 минуты после `docker compose up -d`. Проверьте, что Docker Desktop Running. Команда `docker compose ps` должна показывать сервисы `running` / `healthy`.

**Порт занят**  
Закройте программу, которая слушает 3000 или 5678, либо в `docker-compose.yml` поменяйте левую часть портов, например `"3001:8080"`, и снова `docker compose up -d`.

**n8n: ошибка в ноде GigaChat**  
Неверные credentials или нода не установлена. Переустановите community node, заново сохраните ключ, выберите его во всех подсвеченных нодах.

**Чат отвечает «ошибка подключения к n8n»**  
Неверный Webhook URL в Valves; workflow не Active; используете Test URL без теста. Скопируйте Production URL ещё раз.

**Очень долго нет ответа / timeout**  
Пайплайн длинный. Увеличьте TIMEOUT в Valves Pipe (например 300–600 секунд) и проверьте в n8n вкладку Executions — виден ли прогон и на какой ноде застрял.

**Нужен ли мне ТРИЗ-диплом?**  
Нет. Достаточно понимать свою техническую задачу. Отчёт потом имеет смысл критически перечитать — ИИ ошибается, алгоритм лишь ведёт по шагам.

**Это замена изобретателю / преподавателю?**  
Нет. Это помощник для структурирования рассуждения. Решение и ответственность остаются за человеком.
